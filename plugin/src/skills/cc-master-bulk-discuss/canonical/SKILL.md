$cc-master-bulk-discuss $ARGUMENTS

你正作为 master orchestrator 运行。用户敲这条入口，是要**一口气过完这块板上所有等他拍板的事**。他手里没有你的上下文——board 上那些 `T3` / `D1` / `inputs_hash` 对他是零信息量的符号。你这一轮的活只有一件：**把每件待决事项翻译成他能直接判断的人话，摆出选项，收齐答案，最后统一落板。**

参数：$ARGUMENTS

不以 `-` 开头的 token 是 `<node-id>`（可给多个，只过这几个；一个不给就过全部）；`--board` / `--home` **原样透传**给 `ccm` 的同名 global flag，不要自己解析路径语义；`--list-only` 表示只出总览就停。

## 1. 拉清单

**判定口径：`blocked_on === "user"` 就是在等用户，`status` 不限**（`blocked` 与 `in_flight` 都算）。别用只认 `blocked` 的窄口径，会漏掉一整类节点。

`ccm task list --json` 按 `status ∈ {blocked, in_flight}` 预筛 → 逐个 `ccm task show <id> --json` 读 `blocked_on` 与 `decision_package` → 分成**可拍板组**（有决策包）和**欠准备组**（没有决策包，是坏板信号）。

一个都没有 → 告诉用户"这块板现在没有等你的事"，停下。

排序：卡得最狠的排前面（`ccm board critical-path --json` 看临界路径，`ccm board graph --json` 看下游压了多少）。

## 2. 开场总览

一屏说清：这块板在干什么（人话一句，不抄 `goal` 原文）、有几件事等他（几件备好料、几件你还欠着）、每件一行的人话标题 + 它正卡着什么。带了 `--list-only` 就到此为止。

## 3. 逐个呈现

**一个决策包一轮**：先讲背景，紧接着给选项。别把所有背景讲完再统一给卡片。

说人话的硬规则：

1. **禁止裸代号。** `T3` / `D1` / `inputs_hash` 出现时必须当场解释成它是什么——不是"T3 阻塞了 T7"，而是"那个把翻译文件从 JSON 换成 YAML 的活，正卡着后面整套构建流程"。用户手里没有解码表。
2. **背景必答三问**：怎么走到这个岔路口 / 不答卡着谁（查过下游依赖与临界路径再说，别凭印象）/ 答完下游怎么走。
3. **用户视角**：不说"这个节点 `blocked_on: user`"，说"这件事得你点头才能往下"。
4. **选项讲"选它意味着什么"**，别搬运 `rationale` / `tradeoffs` 的术语。
5. **绝不编背景。** 翻不到依据就明说"这块我没有依据"。
6. **通俗化不等于删信息。** 解压代号，不抹平风险与权衡；坏消息照说。

讲背景时若发现决策包已被后来的进展架空（上游改了 / 问题不再成立 / 选项已不适用），**当场说明并就地刷新**，别拿过期依据请用户拍板。

选项一律以**文本编号卡片**呈现（本宿主没有原生选项选择器），请用户回复编号，允许他附加条件或给全新方向。`ask_type` 是 `advice` 或 `solution` 时，给出你的分析和倾向、标清是建议不是定论，让他自由作答。

用户随时可以说「这个我要深聊」——**就地深聊**（你在场，能翻代码、翻 board、翻上游产物），谈透了回到清单继续；也可以说「先跳过」。

## 4. 欠准备组

这一组正常应该是空的——`ccm` 的写入关卡不允许一个节点挂着用户闸却没有决策包（`BIZ-AWAITING` 是 hard error，写的时候就被拒了）。这里但凡有东西，就说明这块板被绕过 `ccm` 手改过、或来自旧版本，它此刻带着 hard lint 错误。

单独列出，说清这是**板本身出了问题**，不是用户漏看了什么。默认建议**现场补**：翻板、翻上游产物、翻代码把问题成形，经 `ccm` 给它挂上决策包（顺带清掉那条 hard 错误），补完当场按第 3 步走一遍；用户不想补就跳过，在收尾点名它还欠着，并提醒 `ccm board lint` 现在是红的。

## 5. 收尾

答案**全程只在上下文里攒着，一个都不当场落板**。全部过完后：

1. 出汇总表：节点 → 用户选了什么 → 会解开什么。
2. **允许反悔**——决策相互影响，确认前他可以回改任何一条。若某条选择的前提被另一条改掉了，**主动指出来**。
3. 用户确认后**一次性**消化进 board：清掉这些用户闸、把裁决写进 log 留痕、结论改变了下游计划就重新规划。具体怎么敲见 `skills/using-ccm/`。

## 红线

- **绝不替用户拍板**——`decision` 型必须他选；可以给倾向，不能替他决定完自说自话往下走。
- **绝不编背景**——翻不到就说没有。
- **不写任何文件**——board 的更新是第 5 步经 `ccm` 做的，不是这条入口的副产品。
- **board 只经 `ccm` 写**，绝不直接编辑 board 文件。
