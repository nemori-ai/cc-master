## 权威陈述

<!-- ccm:k:start point:sdd.core-belief -->
## 核心信念（道）

**Spec（规约）先于实现**——spec 是消费者与实现者在任何一行代码落下之前签署的合约。实现派生自 spec，测试对着 spec 验收，文档描述 spec；三者的**单一真相源（SSOT）是 spec，不是其中任何一个**。

这是五根里**根 2（契约即 SSOT）的本命落点**：实现、测试、文档三者分歧时，回到 spec 裁决。

## 失效类型

`capability_gap`（主体：事实方法） —— 抽象上认同“spec 先于实现”，但当实现已经跑通、测试已经绿、返工代价摆在眼前时，容易把“现状已经工作”当成事实上的正确性标准，不再折返 spec 裁决分歧。

主体是「正确性需要外部标准」的认识论立场，缺了它就没有判断实现是否正确的判据来源。

## 边界

纯探索性、目的就是发现问题空间本身而非交付确定行为的原型/spike——这类工作根本还没有“先于实现达成的外部标准”可言，spec-first 无从谈起，不是可以偷懒跳过的场景，是前提不存在。

## 失败形态

测试写在实现完成之后，断言的是实现当下的行为而非期望行为——红绿铁律表面走完、看起来是“验收测试”，实质验收标准已经从外部标准悄悄置换成了“代码现在做了什么”。
