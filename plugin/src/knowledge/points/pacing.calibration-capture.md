# 什么时候采集校准语料

<!-- ccm:k:start point:pacing.calibration-capture -->

估算的 band 阈值需要经验语料才能校准，而语料只来自你**主动采集**。在两个时机跑
`ccm calibration capture`：**一次节奏收口时**，以及**一个任务到达终态时**。选这两个锚不是习惯问题——它们是"当初的预测"与"实际结果"同时握在手里的仅有时刻，错过就只剩其中一半，采了也构不成一对观测。

看见 `calibration_status:"uncalibrated-conservative"` 时，**它不是让你别用估算的理由，是提醒你这条回路还没人闭合**。把它当作"不可信所以绕开"，正是让它永远不可信的那个动作。

## 失效类型

`environment_fact`（主体：事实方法） —— 删掉之后，agent 不会知道 ccm 有这个采集命令、更不会知道该在哪两个时机调它；而"要校准预测就得攒预测-实际对"这个道理它本来就懂。

主体是 `ccm calibration capture` 这个命令的存在与它的两个调用锚点，属本工具的具体事实，更强的模型也推不出来。

> 内容轴宪章在提出这条缺口时标的是 `prosthetic`（称其为"感知义肢的反馈半环"）。那个标注写于判据 v3 之前，属叙述性判断而非 schema 字段。按 v3 的顺序过滤器重判：先问主体是行为约束还是事实方法——这一条的主体是"某个命令该在何时调用"，是事实方法；再问把方法部分交给更强的模型能否自己补回来——命令名与板上的时机锚点补不回来，故归 `environment_fact`。附带一提，`prosthetic` 全图仅剩 3 点，该类别的存废本就悬而未决，不宜再往里添。

## 边界

只在板背一个 `asserted` / `confirmed` 交付 DDL 时才有采集价值——没有 DDL 就没有 deadline-risk 预测，也就没有可配对的观测。无 DDL 的编排跳过这一条，不必为了"攒语料"而伪造一个 DDL。

## 失败形态

死环是这样闭合的：估算永远未校准 → 指导说"未校准不可信" → 你更不用估算 → 永远产不出观测语料 → 永远未校准。这个环不是外部约束造成的，是**指导只教了消费侧、没教生产侧**造成的——机制齐备、命令可用、零调用者。同型的另一处是跨编排协调：inbox 的收发机制齐备，只教了怎么发、没教什么时候读，于是实测积压 12 条从未被读。凡是"读的一侧有指导、写的一侧没有"的设施，都该假定它正在空转。
