# 隔离清单 —— 已知失败，快门跳过，但债必须还
#
# 这个清单与 tests/heavy-tests.txt 语义不同，别混用：
#   heavy-tests.txt  收「跑得慢」的，测试本身是好的
#   quarantine.txt   收「已经红了」的，测试本身有问题
#
# ── 为什么要有这个清单 ────────────────────────────────────────────────────────────
#
# issue #213 把 run-tests.sh 的快层接进了每 PR 的 required check。门一旦成真，第一件事
# 就是撞上早已存在的红：下列各条在 main 上红了很久，只是此前没有任何 CI 会跑到它们。
# 当前合计 13 条（2 + 5 + 1 + 5）。这个数字只应下降；它上升时，PR 描述里必须有理由。
#
# 处置有三条路：当场修（与引入门的改动无关，scope 爆炸）、让 CI 不 required（门又假了）、
# 或者登记。选登记，因为它是唯一同时满足「门是真的」与「债是可见的」的选项。
#
# ── 这个清单为什么不会变成垃圾桶 ──────────────────────────────────────────────────
#
# 因为它有反向检查：`bash run-tests.sh --quarantine` 会真跑清单里的文件，任何一个
# **变绿**了却还留在清单上，就是硬错误。清单只许变短。nightly 每天执行这道检查。
#
# 收录门槛（比 heavy 严）：
#   1. 必须是 main 上已存在的失败，附独立复核证据 —— 不许把本次改动引入的红塞进来
#   2. 必须写明失败的**诊断**，不能只写「红了」。写不出诊断说明还没看懂，那就先看懂
#   3. 新增一条，必须在 PR 描述里说明为什么不能当场修
#
# ── 已登记 ────────────────────────────────────────────────────────────────────────
#
# 2026-07-31 独立复核：在 main(0a3b0aeb) 的干净 worktree 上逐个跑过，失败数与诊断一致。

#   release-metadata     tag-gated 断言在非 tag 环境下仍执行——它本该 skip 而非 fail
