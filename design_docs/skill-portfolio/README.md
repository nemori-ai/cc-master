## 2. 两轴各自的一句话结论

**结构轴**：当前 47 个 module 是按 **skill 归属**切的，不是按**认知平面**切的。于是入口、决策、机制三类知识在 `master-orchestrator-guide` 里揉成一团，同一个概念在它和 `using-ccm` 各存一份。动作是：按「读它的人此刻在做什么」重新分五个平面（入口/决策/机制/手艺/回流），让 skill 边界落在平面缝上。

**内容轴**：cc-master 给一个第五代模型的价值**没有一样是教学**，而是补四类结构性缺失——状态义肢、感知义肢、完整性护栏、环境事实。其中**只有「完整性护栏」随模型变强而增值**，「能力补课」与「环境事实」会消亡。操作判据是「再强十倍」测试。由此推出的顺序是：**先补护栏，再删转录**。

## 5. 明确不做

- **不在这次重排里裁剪 point。** 结构轴是重新分区；裁剪走内容轴的 S 类，各自带证据、各自过闸。两件事混在一起会让两件都判不清。
- **不动 `engineering-with-craft` / `authoring-workflows` 的内部结构。** 它们是图上最健康的两个（cohesion ≥1.95、零孤立点），动它们无收益。
- **不引入第 10 个 skill。**
- **不引入 orchestrator 之间的点对点通信。** ADR-032 §2.1 D1 已明令否决；内容轴 M13 补的是**读 inbox / 看花名册**的消费侧，不是发消息。
