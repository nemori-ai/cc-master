# 第 0 层的泄题闸

> 状态：**生效**（2026-08-06）。它是 [`capability-gap-preregistration.md`](capability-gap-preregistration.md) 里每一份提示词的**验收标准**——不过闸的提示词不许拿去跑。
>
> 起因：[`prereg-review-2026-08-06.md`](prereg-review-2026-08-06.md) Q2 的盲测——6 条承重任务，4 道被第三方仅凭题干高把握命中考点。

---

## 1. 为什么必须是一道闸，不能只是几条写作规则

试点（[`exam-first-funnel.md`](exam-first-funnel.md) §11）已经证过一次：**出题者遵守三条明文规则、做了自评、还主动标出自己最没把握的一道，七道题仍然全泄。**

**泄题是写作者自己看不见的。** 他知道答案，所以判断不了「一个不知道答案的人能不能从题干里反推出来」。

所以防线不能是规则，只能是**测量**——这与本轮对隔离做的处置同型：不假设「换个目录就读不到」，而是拿探针去测（结果当场破功）。

## 2. 闸怎么跑

对每一份提示词，**在它被用来跑测之前**：

1. 把提示词**单独**交给一个第三方——不给 `point_id`、不给「一句话它教什么」、不给「不做这条会显形」那段作者旁白、不给知识点原文。
2. 只问两件事：**「这个任务显然期望执行者做什么？」** 和 **「你的把握程度（高 / 中 / 低）」**。
3. 按下表判：

| 第三方的反应 | 判定 | 处置 |
|---|---|---|
| 高把握说出考点核心主张 | **泄** | **提示词打回重写** |
| 中把握、方向对但漏关键维度 | **半泄** | 见 §3 |
| 低把握 / 给出多个互斥候选 / 说不出明确指向 | **未泄** | 放行 |

## 3. 「半泄」按哪层计 —— 跑之前拍板，不留给现场

审查明说这一条它定不了、且应当跑前定。**裁决：半泄按泄处理，打回重写。**

理由是非对称损失（[`measurement-design.md`](measurement-design.md) §6）：把一份半泄的提示词放行，产出的是一个**被高估的正面结论**，而正面结论通向删除侧；打回重写只多花一次出题。**两边代价不对称，就往便宜那边错。**

## 4. ★ 降级必须留痕：判据不许静默串档

这是审查里比「可能不准」严重得多的一条。

**一道泄了题的第 0 层测试，实质上是第 1 层。** 而第 1 层按 §5.1 **只授权「压成线索」，绝不授权删除**。

**而记录格式里此前没有任何字段会留下这个降级痕迹。** 于是流水线会产出它无权产出的删除授权，且事后看不出来。

因此每条结果记录**必须**带这三个字段：

```
leak_gate:        pass | fail            ← 该提示词过没过泄题闸
effective_tier:   0 | 1                  ← leak_gate=fail 则**强制**为 1
max_license:      候选删除批 | 压成线索    ← effective_tier=1 则**强制**为「压成线索」
```

**`effective_tier` 与 `max_license` 是派生字段，不许手填。** 它们由 `leak_gate` 机械决定——留给人填，就等于留了一个把降级抹掉的口子。

## 5. 出题者不得是本表作者

审查指出的一处更基本的问题：**表里只有一句话的设计意图，真正要投喂的提示词并不存在**，按目前安排会由跑测的人现场写。

那等于把 §3 那条效度威胁（作者 / 设计者 / 评分者是同一人）**从设计环节挪到执行环节**，而不是消除它。

**所以：提示词必须在跑测之前写死、入库、过闸。** 现场临时写的提示词一律不合格——不是因为它一定写得差，是因为它**没有经过闸**。

## 6. 这道闸的诚实边界

- 第三方与被测方同族，**它猜得中不代表被测方一定也猜得中**，反之亦然。这道闸给的是**上界估计**（偏保守：宁可判泄）。
- 它测不出「题打偏了」——一道**没打中考点**的题也会「未泄」。承重性由 Q1 那条线单独管，两者不能互相替代。
- 「低把握」是自评，可能不准。缓解：要求第三方**给出具体候选**而不只报把握等级；给不出具体候选的「低把握」才算数。
