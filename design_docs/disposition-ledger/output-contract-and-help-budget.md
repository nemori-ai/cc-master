# `--schema` 输出契约 与 help 预算：两个未决项的裁决

> 状态：**已裁决，待实施**（2026-08-05）。用户拍板。
>
> 本文解掉 [`env-fact-migration-ledger.md` §4](env-fact-migration-ledger.md) 三个未决项中的两个。第三个（静默行为无处安放）仍未决。
>
> 上位判据（用户拍板）：**`--help` 按 Unix CLI 标准与最佳实践承载；help 不适合承载的，由 `using-ccm` 作为技术文档承载。**

---

## 裁决一：`--help` **不分层**，改设预算闸

### 起因

迁移台账担心：语义段迁进 help 后，`--help` 变长，而 agent 每次调用吃全文。Unix 的传统答案是两层——`--help` 简、`man` 详。但 ccm 没有 man，要造就是第二套命令面 + 第二套内容槽 + 双份撰写维护。

### 实测（167 个子命令 help）

| | token |
|---|---:|
| 中位 | **122** |
| p90 | 234 |
| 最大 | 443（`goal deadline *` 一族）|
| 平均 | 145 |

要迁进去的语义段（行为 / 边界 / 幂等 / 落盘路径），按 `calibration capture` 实测约 **+80 token**。迁完中位约 200，p90 约 340。

**对照**：`using-ccm` 的命令目录约 150KB ≈ **47,000 token**，是 skill 加载即常驻的。

### 裁决

**不分层。**

```
分层要解决的：  --help 从 122 涨到 200 token，且只在真调用时付
分层要付出的：  第二套命令面 + 第二套内容槽 + 双份撰写维护
```

数量级不匹配——这是在为一个不存在的问题盖房子。

**替代物：预算闸。** 加一条测试断言「每个 verb 渲染出的 help ≤ N token」。当前 max 443，先定 **500**，迁移完成后按实测收紧。理由与知识图的 router budget 同型：**用一道会红的线管住膨胀，而不是用架构管。** 成本是一个测试文件。

> 预算闸不是摆设：它替代的是「分层」这个架构手段，所以它必须真的会红。定 500 而不是 1000，是为了让下一个想往 help 里塞长篇的人当场被拦。

## 裁决二：新增 `--schema` 能力，且**必须带一致性闸**

### 起因

`ccm.cmd.json-shape`（27.5KB，全库最大的一个知识点）记录每条命令 `--json` 输出的 `data` 形状。Unix help 传统上不承载输出 schema，所以它既进不了 help，留在 skill 又是一份要人维护的副本。

### 现状实测

- 代码里有 **60 个** `schema: 'ccm/xxx/v1'` 常量，**散在各处，没有注册表**。
- `json-shape` 是它们唯一的集中陈述。
- 已有 contract 型测试（`handler-routing-contract.test.ts` 等），但不覆盖输出 schema 声明。

### 命门：换文件后缀不等于拿到 SSOT

若 `--schema` 只是把那 27.5KB 搬进一张 TS 表，**它照样会过期**——只是把副本从 markdown 挪到了 TS。**「接口不会过期」这句话不会因为换了文件后缀就成立。**

三条路：

| 路 | 做法 | 评价 |
|---|---|---|
| A | 手写 schema 表 | 最快，**没解决漂移**，只是换地方放副本 |
| **B** | 手写 + **一致性测试**（跑真命令，拿真输出对声明校验） | **采纳** |
| C | 从构造 payload 的代码派生 | 最正确，但要重构 167 个 handler 的输出路径 |

**采纳 B**，理由与刚落地的 lint 修法表同型：表可以手写，但必须有一道机械闸盯着——`board-lint-remediation.test.ts` 当场抓了作者三条漏网规则，靠的就是那道闸。**没闸的表就是下一个 `json-shape`。**

### 分阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| **1** | `VerbSpec` 加 `outputSchema` 字段；router 拦 `--schema`；help 渲染一行指针 | `ccm task show --schema --json` 返回声明的契约；未声明者诚实返回 `unknown` |
| **2** | 一致性测试：对已声明且可无副作用调用的命令，跑真命令、对声明校验 | 声明与真实输出不符 → 测试红 |
| **3** | 逐步扩覆盖（种子选 board / task / goal 高频只读面） | 覆盖率报告，不设硬指标 |
| **4** | skill 侧：`json-shape` 改为引导 `ccm <cmd> --schema`；**保留**跨命令的 `{ok,data}` 信封契约（那层是跨命令的，归 skill） | 先补接口再删文档，顺序不可反 |

### 三条诚实边界（现在写下，免得日后拿它冒充完成）

1. **覆盖率不可能一步到位。** 大量 write verb、以及需要真 board / 真配额 / 真 harness 的命令，一致性测试跑不全。
2. **未声明的必须诚实报 `unknown`，不许假装有。** 一个骗人的 schema 比没有 schema 更糟——这是本轮反复验证过的同一条道理。
3. **测试只保证「声明了的必须真」，不保证「该声明的都声明了」。** 后者靠覆盖率报告推进，不靠一道假装全覆盖的闸。

### 裁决三：让沉默可被陈述（已实施）

先纠正提出时的一处不准确：**非 `--json` 那一侧本来就打了 `(无此任务)`**，沉默只在 `--json` 一侧。

实施：

| 侧 | 改前 | 改后 |
|---|---|---|
| `--json` | `{"ok":true,"data":null}` | `{"ok":true,"data":null,"not_found":true}` |
| human | `(无此任务)` | `(无此任务：T404)` |

三条设计约束：

1. **不改 `ok` / exit code。** 读一个不存在的 id 是合法的查询结果，不是错误。
2. **`data` 仍是 `null`。** 纯附加字段，按 `data === null` 判断的既有调用方不受影响。
3. **查得到时不出现 `not_found`。** 否则标记失去信息量（已有测试钉住）。

覆盖 `task show` 与 `jc show` 两处 read-by-id 详情。
