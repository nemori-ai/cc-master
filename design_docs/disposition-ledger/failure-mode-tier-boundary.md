# 档位边界：`capability_gap` 与 `motivation_conflict` 之间那条线没画完

> 状态：**判据补充已获用户批准**（2026-08-06）。本文本身不改动任何 `failure_mode`——重判由第二方另行执行。
>
> 起因：[`capability-gap-preregistration.md`](capability-gap-preregistration.md) 指出「87 条里有 22 条的失效类型是用动机措辞写的」。主控机械复核得下界 10。两个数字都对，也都不是问题的形状。

---

## 1. 全量复核：问题比「若干条标错」更结构性

按「失效类型段是否同时含〈主体是…〉与〈压力措辞〉」把全部 **267** 个点分桶：

| 桶 | 点数 | capability_gap | environment_fact | motivation_conflict | prosthetic |
|---|---:|---:|---:|---:|---:|
| **both**（方法主体 + 压力失效） | **62** | 17 | 7 | **37** | 1 |
| pressOnly | 25 | 0 | 5 | 19 | 1 |
| subjOnly | 175 | 69 | 100 | 5 | 1 |
| neither | 5 | 1 | 0 | 2 | 2 |

**两个纯桶高度一致**：`subjOnly` 有 169/175 落在 cap/env，`pressOnly` 有 19/25 落在 motiv。**标注整体是自洽的。**

张力**集中在 `both` 桶**：同时具备方法主体与压力失效的 62 个点，被判成了两种档——**37 : 25**。

> 所以准确的说法不是「有 22 条标错了」，而是：
>
> **62 个点落在同一种情形上，而判据没说这种情形谁优先——于是同一种情形被判成了两种档。**
>
> 这不是标注者不细心。这是**判据在这条边界上没画完**。用一把没画完的尺去重判 22 条，只会得到另一个同样任意的答案。

## 2. 判据缺的是什么

现行顺序过滤器先问「主体是行为约束还是事实方法」。但 `both` 桶的点**两样都是**：

```
goal.trace-and-delta
  主体：Goal Trace Test 三问 + Delta Classifier 四分类   ← 方法框架
  失效：「这么明显有用，先做完再解释也一样」            ← 纯动机

devloop.explore-exploit
  主体：按不确定度调步长的 explore/exploit 判据          ← 方法框架
  失效：「沉没成本会把它拉向顺手做完/做漂亮」            ← 纯动机
```

「主体是什么」和「实际会怎么坏」是**两个问题**，过滤器只问了前一个。

## 3. 判据补充（**已批准**）：回到 `failure_mode` 存在的理由

这个字段存在的唯一目的，是预测**耐久性**——随模型变强，这条知识增值还是贬值。所以 `both` 桶的分野应当直接问那个问题：

> **假设一个更强的模型已经知道这条的全部内容，这条还需要存在吗？**
>
> - **不需要** → 价值在**具体内容**（分类法 / 命令 / 事实）。内容能被推导出来时它就贬值 → `capability_gap` / `environment_fact`。
> - **仍需要** → 价值在于它是一条**预先立好、用来对抗压力的规则**。模型越强，压力下的合理化越有说服力，它越增值 → `motivation_conflict`。

这就是宪章里那条「10 倍强的模型」试金石，只是此前没被用在这条边界上。

按它重看上面两例：两条都自陈「模型完全清楚该怎么做」，坏在压力——**按补充判据都该是 `motivation_conflict`**。

### 一个反例，说明补充判据不是把 `both` 桶一刀切

`conduct.deserting-podium` 的主体是「把各种坏编排归一为『离席』的四方向诊断框架与命名技术」。更强的模型能自己发明**一套**分类，但**这一套**是系统内共享词汇——hook 注入、skill 之间靠它对齐。**具体内容在这里是承重的**，所以它留在 `capability_gap` 一侧站得住。

判据因此可执行：**问这条的价值是否绑定在它的具体措辞/分类上。绑定 → cap/env；可换成任何等价物而不损失 → 护栏。**

## 4. 影响面与为什么本轮不改

按补充判据需要重判的是 **`both` 桶全部 62 条**（不只是那 25 条异侧的——37 条同侧的也该用同一把尺过一遍，否则新判据只对半边生效）。

**本轮不改任何 `failure_mode`**，三条理由：

1. **判据修订本身要先被批。** 拿一把刚改过、还没人审的尺去动 62 个点，是在既有 80% 置信上限之上再叠一层未验证的判断。
2. **重判会改分母。** 能力补课档若从 87 缩到 70 上下，预注册表的测试范围、实测预算、路线表都要跟着改——那不该在同一步里悄悄发生。
3. **同一个人不能既改判据又用它重判。** 这与预注册表拆分「设计」和「跑分」的理由完全相同（方案 §3 的效度威胁）。
