## 6. 两起装置事故，如实记账

### 6.1 跑测中途 `claude` 二进制被替换（与第 0 层同型复发）

首轮 57×2 跑到一半，`claude` 二进制在 11:49 被整个替换，`spawn ... EACCES`：**第一趟掉 23 份，第二趟直接硬崩、无输出文件**。且崩溃点前后骑在版本切换上，产物版本不纯。

**处置：首轮全部作废，不做「补跑掉的那些拼回去」。** 拼回去会得到一批跨两个版本的产物，而这正是第 0 层那轮明确拒绝过的论证形态。改为**把二进制复制成一份本地副本钉死**（`scratchpad/bin/claude`，2.1.223），把整批 114 份重跑一遍——这样「全部产物同一版本」是机械成立的，不靠推断。代价是白跑了约一轮。

### 6.2 装置会把「没答题」记成 `ok`（本轮新发现）

`exam-closed-book.mjs` 只看退出码。而在 `--tools ""` 下，模型有时会先说「我先看一眼工作目录」然后**幻觉出一段工具调用与工具返回**就停住——进程退出码 0，装置记 `status: ok`，产物却根本不含答案。首轮 114 份里命中 **10 份**（约 9%）。其中一份还幻觉出了一整个伪造的对话轮次。

这类产物如果直接进评分，会被判成 `unknown` —— 而 `unknown` 在本层通向「留」，方向虽保守，**但那是伪造出来的数据，不是证据**。

**处置：加一道空产物检测（长度阈值 + 幻觉工具调用特征串），命中即重跑，最多三轮；仍空则记掉出，不拿它冒充 `unknown`。** 重跑后 114 份全部为真实答案，掉出 0。

> 这一条建议回流给装置本身：`exam-closed-book.mjs` 目前的 `ok` 只等于「进程正常退出」，不等于「拿到了产物」。第 0 层那 65 份是在没有这道检测的情况下跑的，**其中有没有同类空产物，本轮无从追认**。

## 7. 这轮测不到的（诚实边界）
