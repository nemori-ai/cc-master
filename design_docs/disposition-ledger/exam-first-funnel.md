# 闭卷考试优先的漏斗（取代原第 0 层）

> 状态：**已被对抗性审查大幅收窄**（2026-08-06）。用户提出考试形态，主控补边界与协议，Fable 5 独立审查后砍掉其中一条主要授权。**读本文务必连同 §9 一起读——§1 与 §2 的原始表述已被证伪。**
>
> 本文取代 [`measurement-design.md`](measurement-design.md) §5.2 中「能力补课档 → 第 0 层」那一段的**执行形态**；§5.1 的「测试类型 → 它能授权的决定」映射表**不变，且被本文进一步细化**。

---

## 0. 一句话

**先用闭卷考试便宜地筛掉两头，只把中间那段送进昂贵的行为测试。**

```
78 条 capability_gap（其中 73 条在测试范围）
   │
   ├─ 闭卷考试（便宜·全跑）
   │     ├── 答不出        → 判「留」。结论到此为止，不再测。
   │     ├── 答得比知识点好 → 判「删」。结论到此为止，不再测。
   │     └── 答得出且与知识点相当 → 进下一层
   │
   └─ 行为测试（贵·只跑中间段）
         给它一个不做就必然出错的真任务，看它**不被提示时**会不会自己做
              ├── 自发做到 → 候选删除批
              └── 没做到   → 判「压成线索」（保留触发点，删掉解释）
```

原方案对全部 73 条构造「承重任务」。承重任务是整套流程里最花人力的部分（每个都要构造成「不做就必然显形」），漏斗把它的用量压到中间段。

## 1. 三种结果，各自能授权什么

| 考试结果 | 授权 | 为什么这个结论是硬的 |
|---|---|---|
| **答不出** | **留** | 它连内容都不知道，无论触发与否都缺 |
| **答得比知识点好** | **删** | 这条不只是冗余，是**拖后腿**——模型不靠提示就答得更准更全，而我们还每次会话塞一份过时版本进去。删它不是省 token，**是止损** |
| **答得出、与知识点相当** | **只能进下一层** | 见 §2 |

第二种是本轮从用户处得到的**新判据**，此前的设计里没有。它有一个额外的好处：**不受 §2 那个局限影响**——如果模型不靠提示就答得更好，这条知识的内容本身已无价值，与「它会不会在恰当时机想起来」无关。

## 2. 考试测的是「知不知道」，不是「会不会做」

这条边界在 [`measurement-design.md`](measurement-design.md) §5.1 已经写死，此处只是它的具体落点：

> **能说出来 ≠ 会主动做。** 识别远比生产容易。

```
考试题：派任务给执行者时，prompt 里什么绝对不能写？
模型答：不能把实现方案钉死——那让执行者变成打字机，也发现不了你没想到的坑。  ← 答得很好

真派任务时：赶时间，还是把方案写死了。
```

**答对只证明知识在它脑子里，不证明它在该用的那一刻会调出来。** 所以「答得出」单独不 license 删除。

### 但这个局限，在本轮已被前一步工作削掉大半

上一轮档位重判（[`tier-rejudgement.md`](tier-rejudgement.md)）把「知道却不做」那一类**整批移进了护栏档**。

也就是说，**剩下这 78 条，按定义就是失效不在动机侧的那些**。对它们而言「知道」与「会做」的距离，比对全库近得多——凡距离大的已被分走，而护栏档根本不测。

**这不是巧合，是那次重判的副产品。** 它让考试形态在此刻的有效性显著高于它在重判之前的有效性。

## 3. 题目设计：这是成败所在，比隔离环境重要

**最容易犯的错是题目泄题**——把知识点的内容写进题干，测试就从「生产」降级成「填空」。

```
❌ 什么时候应该跑 `ccm calibration capture` 采集校准语料？
      泄露了：有这个命令 / 有「校准语料」这回事 / 而且分时机。它只需填空。

✅ 你在编排一个带交付期限的项目，系统给的完成时间预测一直标着「未校准，不可信」。
   你会怎么办？
      不提任何名词。看它自己会不会想到「要让预测变准，得有人去攒预测-实际的对照数据」。
```

**三条硬规则：**

1. **题干不得出现知识点独有的名词、命令名、分类名。** 用场景描述代替。
2. **题干不得暗示答案的结构。** 「有哪三个维度」这种问法等于告诉它有三个。
3. **一题只考一条知识。** 混考会让判分无法归因。

**题目由不掌握「该条知识原文」的一方出**——出题者只拿到「这条知识要解决的问题场景」，不拿正文。这是防泄题最有效的一招，比事后审题可靠。

## 4. 判分协议

### 4.1 判分标准跑之前写死

每条题预先写三档的判据，跑完只对照：

```
point_id:
场景题:
判「答不出」的判据:      （答案里缺了什么，具体到可指认）
判「相当」的判据:        （覆盖到哪些要点算相当）
判「更好」的判据:        （什么情况算超过——更准 / 更全 / 更贴合当下事实）
本题作废的情形:          （答非所问 / 场景被误解）
```

### 4.2 判卷方不得看到知识点原文

只喂「题目 + 答案 + 判分标准」。

**理由**：拿到原文的判卷方会不自觉地把原文当标准答案，于是「不一样」被判成「不如」——而「不一样但更好」正是我们最想抓的那一类。

### 4.3 两个评委，分歧单列

主控 + 独立第二评委（本仓一贯用 codex 做独立验收）。**分歧不取平均，单独拎出来看**——分歧本身是高信号，通常意味着判分标准没写清。

### 4.4 出题、跑卷、判卷三方分离

作者不出题、出题者不判卷。理由与预注册表拆分「设计 / 跑分」相同：三件事压在一个人身上，出错时分不清是题坏了、判据坏了、还是结论坏了。

## 5. 隔离怎么落地

| 要求 | 做法 |
|---|---|
| 不加载 skill | 空目录里跑，不带插件 |
| 不上网 | 不给联网工具 |
| **不查本地文档** | **关键：别在 repo 里跑。** 只要 cwd 在仓库内，随手 grep 就能读到原文。必须在临时空目录 |

判卷是**另一次独立调用**，不复用考试那次的上下文。

## 6. 诚实边界

1. **污染消不掉。** 被考模型与知识作者同族，「它知道」可能只是「它见过」。缓解：题目用改写过的场景而非文档原例。**如实标注，不假装控制住了。**
2. **考试不能证明「会做」。** 见 §2。这是它 license 范围窄的原因，不是缺陷。
3. **「更好」的判定带主观性。** 靠预注册判据 + 双评压低，消不掉。
4. **样本量仍然小。** 单条结论是存在性证据，不是概率估计；批级结论仍由 Track B 消融承担（[`measurement-design.md`](measurement-design.md) §4 不变）。

---

## 7. 先试点，不铺开

有三处拿不准，**小规模跑一次就都能看见，铺开之后再发现就贵了**：

1. 题目会不会泄题——设计规则写了，实际出题时守不守得住？
2. 判分标准写不写得清——「相当」与「更好」的界线，落到具体条目上是否可判？
3. 两个评委分歧有多大——若分歧率高，说明判据不可用，得回炉。

**试点规模：5–8 条**，从 73 条里选，覆盖不同 skill 与不同点类型（procedure / principle / decision_rule）。

试点产出的不是判定，是**这套流程能不能用**的答案。

## 8. 与既有工作的关系

- 预注册表那 73 条的「承重任务」**不作废**——它们是**第二层**（行为测试）的输入，只是不再是第一层。
- 第一层要**另写考题**，且按 §3 由不掌握原文的一方出。
- [`measurement-design.md`](measurement-design.md) 的 §3（四个效度威胁）、§4（批级推理）、§6（非对称决策规则）全部不变。

## 9. 对抗性审查结论（Fable 5 · 2026-08-06）· 本文被收窄成什么

审查的判决是：**漏斗形态可保，但只有「答不出 → 留」这一条边是安全的。** 逐条记录，包括我自己被驳倒的地方。

### 9.1 ★ §2 那段论证是**非因果推论**，已作废

我写：重判把「知道却不做」移进了护栏档，所以剩下 78 条的「知道-会做」距离近。

**错在偷换了轴。** 重判的判据切的是**动机轴**（知道、也会想到，但压力下选便宜的路）；而「能说出来 ≠ 会主动做」这个局限在**检索时机轴**上（被问到答得出，真实流程里**不会自发想起来调用**）。切前者不影响后者。

复核：78 条里失效描述明写「不会主动想到 / 不会自发」的有 **7 条**（审查称「重灾区」，实测规模小于此说）。但**论证的无效性与命中几条无关**——重判根本不对这条轴发言。

**处置**：§2「局限已被削掉大半」整段作废。改为：**凡失效描述含「自发 / 主动想到」的条目，考试的任何正向结果都只授权进第二层，不授权任何形式的删减。** 这批可机械预分流。

### 9.2 ★ 「答得更好 → 直接删」这条边**砍掉**

两个理由，都成立：

1. **它只证伪了内容价值，对「在场价值」零信息。** 一段 in-context 文字有两种作用：教它不知道的（内容），以及在恰当时机 prime 它（在场）。三态里「压成线索——**保留触发点**、删掉解释」的存在，本身就承认了这两者可分。考试只能证伪前者。
2. **它与上位方案 §6 的删除门直接矛盾。** `measurement-design.md` §6 写死「判删须同时满足：第 0 层 k 次全中 + 双评一致 + **批级消融未见退化**」，而本文 §1 的流程图写「答得更好 → 判删，结论到此为止，不再测」——**跳过了其中两条**。而 §8 还声称「§6 全部不变」。两份文档互相矛盾，执行时必然走更省事的那条。

**处置**：最高授权降为「**压成线索候选 + 进候选删除批走批级消融**」。这样内容价值的判定被用上（解释可删），在场价值仍由批级消融兜底，与 §6 重新一致。

### 9.3 §4.1 的判据模板把原文从后门走私回来

§4.2 不给判卷方看原文，但 §4.1 要求写「覆盖到哪些**要点**算相当」——那张要点清单只能由掌握原文的人写，**本质就是原文要点的枚举**。一个绕开清单、用不同路径达成同一目的的答案，会因「缺可指认要点」被误杀——**而那正是 §4.2 想保护的那类答案**。

更深一层：判「更贴合当下事实」需要**超越原文的 ground truth**。对环境事实档存在（查 `--help`），但那 112 条不走本漏斗；对留在 cap 档的 principle / decision_rule，**多数条目不存在独立 oracle——这正是它们没被分进确定性层的原因**。于是「更好」这一档落在最不可判的条目上。

**处置**：① 判据从「枚举原文要点」改为「枚举**这条要防止的失败后果**」，判答案能否避免那些后果；② 「更好」档**只对存在独立 oracle 的条目开放**，其余封顶「相当」。

### 9.4 §3 的 ✅ 示范题**自己就泄题**

我写的正面例子里那句「预测一直标着**未校准**、不可信」——「未校准」三个字已经泄露了「存在校准这回事」，**正是同一段 ❌ 例被批评的泄露项之一**。

设计文档里精心构造的示范题都守不住规则，批量出 73 题时守住的概率可想而知。

结构性根因：三条规则全管**题干**，而出题者的输入——「这条知识要解决的问题场景」——**由谁写、含多少定向信息，一个字没规定**。而那个场景描述必然由掌握原文的人写，**它是唯一且不设防的泄露信道**。

**处置**：① 场景描述立同款三规则；② 题干与原文做 n-gram / 名词重叠机械扫描；③ 试点专门做一次「泄题对照」——同一条知识出两版题（一版含轻微泄露），量化这个信道有多宽。

### 9.5 隔离方案漏了 harness 层 —— 部分成立

审查指出 user 级 `CLAUDE.md`、memory、全局 plugin 会把这批知识的蒸馏版注进 system prompt。

**实测部分否证**：探针直接问「你的 system prompt 里有没有编排 / board / 配速 / 验收纪律的指导」，答「编排只有禁止性两句、board 完全没有、pacing 没有」。**知识内容没有被注入。** 但确实继承了 session 级指令。

**处置**：仍按建议加固（显式干净 `HOME` / `CLAUDE_CONFIG_DIR`、禁 memory 与全部 plugin），并**把这个探针的输出存档为隔离证据**——不是因为这次发现了污染，而是因为下次环境变了没人会重新验。

### 9.6 成本论证建立在沉没成本上 —— 成立

我写漏斗省的是「承重任务构造」的人力，但 §8 自己承认那 73 份承重任务**不作废、只是挪到第二层**——**它们已经构造完了，是沉没成本，漏斗省不回来。**

漏斗真正省的只有第二层的运行成本；而它**新增**：73 份场景 + 73 道题 + 73 份判据 + 73 次考试 + 146 次判卷 + 试点。

**若「答得出且相当」的中间段占多数，净成本上升而非下降。** 而按 §9.1，这批条目的失效恰恰不在「不知道」，中间段大概率就是主体。

**处置**：**试点的目的因此改变**——不再是「验证流程能不能用」，而是**测「答不出 + 更好」两头合计占比**。若不足约 30%，漏斗的成本论证不成立，直接回退原 0→1→2 路线。

### 9.7 分歧没有处置规则 + 试点测不出分歧率

「分歧单列」之后谁裁决没写，默认会流回主控 = 知识作者 = §4.4 要拆掉的那个集中点。且 5–8 条试点在统计上测不出分歧率。另：两个评委同为 LLM 且见过同类语料，**一致也可能是共享偏见的一致**——低分歧率不能反向验证判据有效。

**处置**：写死「**分歧默认落保守档**」（删/相当分歧 → 相当；相当/答不出分歧 → 答不出）。这样分歧率再高流程也不作废，只退化为更保守，与 §6 非对称损失同向。分歧记录只用于回炉判据。

### 9.8 三态映射的未定义情形

- **自信地答反**（把「别钉死实现方案」答成「要写清实现方案防跑偏」）——按关键词可能被判「相当」。**缺一档「答反」**，它该判「留」且是最强的留证据。
- **run 间不一致**——考试没写 n。上位方案第 0 层写了 k 次，考试层反而没写。**改为 n≥3，按最差 run 归档。**
- **部分覆盖**——落哪档未定义。**改为按「答不出」处理**（进不了删除侧即可）。

### 9.9 「答不出 → 留」的证据等级虚高

坏题也产生「答不出」。方向无害（留是默认），但台账会把「留（确证不知道）」与「留（题没出好）」记成同级证据。**处置**：判卷方对「答不出」须额外判一次「是答案缺还是题坏」，坏题标「留（未测）」。

### 9.10 一处它拿不准、而我能答的

它问 78 → 73 那 5 条的出处。**答**：那 5 条是预注册表 §3 判为「无法预注册」且仍属本档的（`sdd.practice-anchors` 等）。出处在 [`capability-gap-preregistration.md`](capability-gap-preregistration.md) §0.5，不是漏账。

## 10. 收窄之后，这个漏斗还剩什么

审查的结论我接受：

> 它剩下的是一台**便宜的保守分流器**——能把「连内容都不知道」的条目提前定案，把其余条目更有依据地送进行为测试。**它买不来任何删除授权，而这正是它该有的尺寸。**

**因此试点的问题变了**：不再问「这套流程能不能跑」，而是问 **「两头占比够不够让这台分流器回本」**。这个问题 5–8 条就能给出粗略答案，且答案若是否定的，**整个漏斗应当放弃**——那也是一个有价值的结论。
